Summary

Real-time overview of the proxy. Stats cards show aggregate counts across all providers. Quick controls let you switch between enforce and shadow mode, and between fail-closed and fail-open, without restarting the daemon.

Quick Controls
Operation Mode
Enforce: blocks and redacts requests containing secrets/PII. Shadow: logs findings without blocking (for testing).
Fail Policy
Closed: if the detection engine fails, the request is rejected (no leak). Open: if the engine fails, the request passes through (availability over safety).

Add / Update Upstream

Name: identifier used in the request path (e.g. openai routes /openai/* to this upstream).
URL: the provider's base URL (must start with https://).
Auth header: which HTTP header carries the API key. The proxy does NOT store or manage your API key — your agent sends it in every request and Cerberus just passes it through. This field tells the proxy which header to preserve (not redact) when forwarding.

Category Actions

Override the default action for an entire category. Categories are: secrets (API keys, tokens, PEM keys), pii (emails, phone numbers), internal_code (internal references). The action can be block (reject the request), redact (replace the value), warn (log but pass through), or allow (skip detection).

Installed Rule Packs

Signed rule packs extend or replace the default detection rules. Packs are Ed25519-signed and verified against a trust root at boot. A tampered pack is deactivated and persisted (fail-closed). Without a trust root, the engine boots with 0 packs.

What is Cerberus?

DLP Firewall

A Data Loss Prevention firewall for LLM agents. Sits between your agent and the provider, scanning every request for secrets and PII.

Zero Leak

Raw secrets never stored. Only SHA-256 hashes, flags, and counts are persisted to the audit store.

< 1 ms p99

Linear-time regex (RE2-like). No backtracking, no catastrophic regex. Async audit writes (non-blocking).

1
Agent sends request to 127.0.0.1:8787
↓
2
Cerberus decodes body, scans with 13 regex rules
↓
3
Action: block (403), redact (replace), warn (log), or allow
↓
4
Audit: event persisted to SQLite (hashes only, never raw values)
↓
5
Forward: sanitized request sent to the LLM provider
Quick Start (CLI)

1. Initialize

Auto-detects installed agents and creates the config.

cerberus init

2. Start

Start the local proxy daemon on port 8787.

cerberus start

3. Route

Point your agent at Cerberus.

export CLAUDE_CODE_BASE_URL=http://127.0.0.1:8787

4. Test

Verify detection works.

cerberus test "my key is sk-abc..."
Chaining with other proxies

Chain Cerberus to another local proxy (e.g. headroom for token compression). Cerberus scans first, then the chained proxy compresses, then the request reaches the provider.

headroom proxy --port 8788
cerberus start --port 8787 --chain http://127.0.0.1:8788
export CLAUDE_CODE_BASE_URL=http://127.0.0.1:8787

→ Cerberus (DLP)

Scans for secrets and PII. Blocks or redacts before forwarding.

→ headroom (compression)

Compresses the sanitized request to reduce token usage.

→ LLM provider

Receives a clean, compressed request. No secrets, fewer tokens.

Stat cards (total events, providers, tools, flags) + quick toggles for operation mode and fail policy + last 10 events.

Events tab

Audit log with provider filter. Each event shows timestamp, tool, provider, action, and flags.

Add, update, or remove provider backends. The proxy forwards to the matching upstream by path prefix.

Install or rollback Ed25519-signed rule packs (Pro tier). The browser reads the file and sends bytes, never a path.

Security

Zero Leak

Raw secrets never written to disk, logs, telemetry, or notifications. Only SHA-256 hashes.

Fail-Closed

If the engine fails, requests are rejected (not leaked). Configurable: closed (default) or open.

No ReDoS

Linear-time regex engine (RE2-like). All patterns verified with adversarial fuzzing.

< 1 ms p99

Sub-millisecond scan latency on a modern laptop. Async audit writes (non-blocking).

Break-Glass

The X-Cerberus-Bypass header allows one-time bypass with an audited reason.

MITM Opt-In

TLS interception is off by default. Requires explicit CA generation + host allowlist (exact match).
