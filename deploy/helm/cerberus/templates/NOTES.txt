{{- if .Values.config.admin.enabled }}
1. Cerberus requires an admin token >= 24 chars. Make sure you installed it with
   `--set config.admin.token="$CERBERUS_ADMIN_TOKEN"` (install FAILS without it).
   The pod receives it via the Storage Secret `{{ include "cerberus.fullname" . }}-admin`.

2. Verify the daemon is alive and healthy:
   kubectl get pods -l {{ include "cerberus.selectorLabels" . }}
   # or with the test hook:
   helm test {{ .Release.Name }}

3. Forward to the proxy (Mode A — self-host on your fleet):
   kubectl port-forward svc/{{ include "cerberus.fullname" . }} {{ .Values.service.port }}:{{ .Values.service.port }}
   export OPENCODE_BASE_URL=http://127.0.0.1:{{ .Values.service.port }}
   export CERBERUS_ADMIN_TOKEN="$CERBERUS_ADMIN_TOKEN"  # same token used at install

4. Configure the backend URL (upstreams) if the defaults don't work for you:
   helm upgrade {{ .Release.Name }} . \
     --set config.upstreams.openai.url="https://gateway.my-corp.com/v1" \
     ...
   ---- either way, inspect the config.yaml mounted in the pod:
   kubectl get cm {{ include "cerberus.fullname" . }}-config -o yaml

Telemetry: OFF by default. To enable it (conscious opt-in):
   --set config.telemetry.enabled=true --set config.telemetry.endpoint='https://your-endpoint/v1'
The payload only carries anonymous metrics (version, os, rule_count, event_count,
uptime, install_id) — never secrets or content. Policy: `cerberus telemetry policy`.
{{- else }}
Cerberus deployed WITHOUT an admin token (use
   kubectl port-forward svc/{{ include "cerberus.fullname" . }} {{ .Values.service.port }}:{{ .Values.service.port }}
But note: the daemon refuses to listen on non-loopback interfaces without a token; if
the daemon fails to start, reinstall with config.admin.enabled=true.
{{- end }}
