## 5. BLOCKER 3 (attempt-5 NEW) — HIGH: widened PAN separator classes break §5 budgets at typical-proxy size

`pii.credit_card` pattern `(?:(?:[ \u00a0]{1,3}|[./-])?[0-9]){12,}` (default_pack.rs:149). Measured worst classes:

- mixed dot/slash/NBSP/space PAN runs, single line: **p50 6.5 ms @ 50 KB, p99 14.1 ms @ 100 KB**. §5 protects "typical prompts (≤ 50 KB)" with p99 **< 3–5 ms** — violated at its own reference size; the < 1 ms/100 KB scan gate (F1.3) is 13–14× over.
- NBSP-only run "4\u{a0}…": **17.0/18.1 ms @ 100 KB** (≈170 ns/byte vs 3.3 ns/byte clean ASCII — 50× constant-factor inflation of the shipped hot path; attacker- or CSV-padding-reachable).
- Mechanism: (a) the `{1,3}`-over-NBSP + `[./-]` alternation makes the automaton ambiguous per byte → regex crate falls to its NFA/PikeVM path for these inputs (still linear — confirmed); (b) greedy `{12,}` chains across space+digit so a single "match" can span a whole line → every PAN pair on one line becomes one >38-byte match rejected by `maxLength` **before** validators (ordering invariant from attempt 4 still holds; no validator amplification — findings=0 in every probe row above confirms this).
- Realistic one-PAN-per-line density costs 1.8–3.6 ms/100 KB (in guard), so the violation class is ≥2 space-separated PANs on one line (transaction CSVs/logs) or NBSP padding — precisely the input space attempt 5 *added*. Not a DoS (bounded, linear); it is a §5/§8B "no-threshold-move" budget FAIL.
- Fix direction (builder): replace the unbounded chain with a bounded, less-ambiguous shape (e.g. anchor the group count `{12,18}` with explicit post-strips, or per-separator prefilter via Aho-Corasick literals, or digit-run precheck before the wide regex); add these three payloads as permanent `load_test` guards asserted at the **plan budgets (1 ms/100 KB, 5 ms p99 @50 KB)**, not the loose 250 ms/15 ms CI ceilings.
- Side observation (cross-post to correctness panel, outside my authority): because of (b), `4000.0566.5566.5556 4111111111111111` on one line yields **zero** card findings — detection loss on the same mechanism; correctness must confirm intended.
